# SchoolFlow: модули и сценарии

## Стек

HTML, CSS, JavaScript без сборщика и сторонних зависимостей. Сервер: Python 3.10+ и SQLite. Интерфейс использует системный гротеск, локальные outline SVG-иконки, нейтральные поверхности и один синий акцент. Светлая и матовая графитовая темы работают без внешних ресурсов.

## Модули

| Файл | Ответственность |
| --- | --- |
| `server.py` | HTTP, сессии, вход, регистрация, общая проверка прав и команды оператора |
| `domain.py` | Схема мероприятия, расписание, задачи и проверка баллов |
| `workspace.py` | Профили, одноразовые приглашения, состав, доступы, администрация и проекция рейтинга для ученика |
| `js/main.js` | Подтверждённое состояние, операции с работами, экспорт, маршруты и базовое отображение |
| `js/workspace.js` | Мониторинг, настройки мероприятия, аккаунт, состав, приглашения и административные формы |
| `js/core.js` | Чистые операции CSV, статистики и рейтинга |
| `js/theme.js` | Тема, системное предпочтение и сохранение выбора |
| `js/icons.js` | Локальный набор SVG-иконок |
| `css/style.css` | Переменные палитры, адаптивные компоненты, состояния и печать |

## Навигация

Раздел хранится в URL: `#dashboard`, `#results`, `#account` и т.д. При F5 серверная сессия восстанавливается, затем открывается разрешённый раздел из URL. «Назад» и «Вперёд» работают через историю браузера. Недоступный роли маршрут переводится на мониторинг/обзор. Переходы между разделами не перезагружают страницу.

Предыдущая версия сбрасывала раздел, потому что меняла только классы элементов в DOM и всегда начинала с обзора при повторном запуске JavaScript.

## Данные и роли

- `events`: одно мероприятие, JSON с настройками, задачами и работами; номер версии защищает запись от конфликтов.
- `profiles`: имя, школа, класс, email и предпочтение уведомлений.
- `memberships`: связь логина ученика с конкретной работой, статус `pending/active/frozen/detached`.
- `invites`: хеш одноразового кода, класс, необязательный email, срок, автор и состояние использования.
- `users`: учётные записи и роли `student/teacher/admin`.

Личный результат определяется через явную связь аккаунта с работой, а не совпадение имени. Учитель может поменять эту связь, если результаты уже импортированы из CSV. Отвязка не удаляет работу и баллы. Заморозка ограничивает доступ к результатам, но оставляет настройки аккаунта доступными.

Ученик получает только разрешённую сервером проекцию рейтинга. При режиме шифров имена других участников заменяются до отправки ответа. Если общий рейтинг закрыт, ученик получает свою запись и действительное место, без чужих результатов.

## Приглашения

1. Учитель выбирает класс и создаёт один код либо пакет по email (до 100 адресов).
2. Полные ссылки доступны в диалоге после создания; сервер хранит хеши, не исходные коды.
3. Ссылка ведёт на `#register?invite=...`. Регистрация и использование кода выполняются в одной транзакции.
4. Если аккаунт уже существует, ученик вводит код или ссылку на мониторе.
5. Участие ожидает подтверждения либо сразу становится активным — по настройке мероприятия.

Код одноразовый, действует 7 дней; его можно отменить. Указанный email должен совпадать с email профиля. Это сопоставление адресов, а не проверка владения почтой. Почтовая доставка и подтверждение email в этой версии не реализованы; интерфейс этого не обещает.

## Настройки мероприятия и задачи

Доступны название, предмет, школа, описание, расписание, статус, подтверждение участия и видимость рейтинга. Время хранится с часовым поясом, отображается в часовом поясе браузера.

Задачи задаются строками `код | название | максимум` (до 20). Максимум мероприятия равен сумме максимумов задач. Баллы каждой задачи проверяются сервером, итог рассчитывается автоматически. Старые общие баллы сохраняются до явного ввода баллов задач. Удаление задачи с имеющимися баллами блокируется, чтобы настройки не стирали результаты.

Расписание информирует о времени мероприятия; платформа пока не принимает решения задач и не является системой экзамена с принудительным таймером отправки.

## Аккаунт и администрирование

Профиль не позволяет самостоятельно сменить роль. Смена пароля проверяет текущий пароль и отзывает все сессии аккаунта. Нужен повторный вход.

Первый администратор назначается оператором существующему аккаунту:

```sh
python server.py --make-admin login
```

После команды сервер запускается обычным способом. Администратор получает таблицу аккаунтов, управление ролями и глобальное отключение доступа. Последнего активного администратора нельзя отключить или понизить. Права проверяются по актуальной записи пользователя, а не только по роли, сохранённой при входе.

## Живое обновление

Мониторинг и рейтинг перечитывают данные раз в 15 секунд в открытом видимом разделе, если другая операция не выполняется. Это polling, не WebSocket. Таймер времени обновляется каждую секунду. Предпочтение уведомлений управляет сообщением об изменениях в открытом приложении, не email-рассылкой.

## Проверка

```sh
python tests/server_test.py
node tests/core.test.cjs
node tests/theme.test.cjs
node tests/ui.test.cjs
```

15 серверных сценариев включают одноразовость, срок и отмену приглашений, подтверждение, заморозку, отвязку, приватный рейтинг, задачи, смену пароля, отзыв сессий и администратора. DOM-проверки включают маршруты и сохранение старого общего балла при изменении имени. Браузерная проверка выполнена на синтетических данных: светлый обзор, графитовый рейтинг, личная строка, расписание, F5 в настройках и ширина 768 px. Печать визуально в этой итерации не проверялась.

## Ограничения

Одно общее мероприятие. Инвайты и профили хранятся в SQLite и не входят в JSON мероприятия; полная резервная копия — согласованный снимок всей SQLite-базы. Нет автоматической рассылки, проверки владения email, решений задач и нескольких независимых организаций. Следующие этапы: несколько мероприятий и миграции, аудит действий, полноформатные браузерные тесты и проверка печати.
